08-07 installment. Both are unambiguous. The eight 08-10 rows differ from their
true date's NAV by only ~0.1%, inside the ambiguity of matching a NAV by value

- `nav` / `current_value` / `gain_loss` / `gain_loss_percent` / `expected_xirr`
  deliberately left stale — all derived, and the SIP backfill recomputes them
  from the corrected base. Hence the ordering: correct the data, **then** deploy.
- Each `UPDATE` is gated on the old `price_per_unit`, so a re-run matches zero
  rows. Verified after commit.
- Both rows carry an audit note recording the old value and why it was wrong.

Ran as a single `BEGIN … COMMIT` after a dry run of the identical script ending

New `docs/OPERATIONS-RUNBOOK.md`, eight sections:

   and that ONE prod container runs four things: Postgres (bound to 127.0.0.1,

## meta: reusable CLAUDE.md audit prompt

Written to `~/.claude/prompts/audit-claude-md.md` (outside the repo — global tool,
not project content). A 5-step prompt for auditing any project's CLAUDE.md,
derived from what actually went wrong here rather than from general principles:

1. **Find what is actively WRONG first** — stale instructions get followed, which
   is worse than gaps. Hunt procedures that bypass a safety script, false absolutes
   ("no test suite"), stale ports/paths/emails, superseded "read X first" pointers,
   and reversed direction decisions.
2. Coverage check against 10 things a cold session needs.
3. Write fixes as tables, every rule carrying the incident that caused it.
4. Compress — measure section shares; anything over ~30% is probably archive; move
   it, and check first whether CLAUDE.md is its only home.
5. Report the wrong-claims table and the diff; don't commit.

It also mandates verifying claims against `package.json`/`ls`/`git grep` rather
than paraphrasing, and specifically bans `git show <branch>:<path> | grep` in shell
loops, which returned false zeros twice today.
