# Changes — 2026-09-09

## fix(amfi): NAVAll.txt went 6 columns → 8; parser silently dropped every fund

**Area:** `src/lib/services/amfi.ts`, `src/app/api/cron/tick/route.ts`,
`scripts/check-amfi-nav-feed.mjs` (new)

### What broke

AMFI changed the layout of `NAVAll.txt`, splitting the scheme name into three
fields (`Scheme Name` / `Plan` / `Option`), taking the row from 6 columns to 8:

```
118989;INF179K01XQ0;-;HDFC Mid Cap Fund;Direct Plan;Growth Option;233.745;08-Sep-2026
  [0]      [1]      [2]      [3]           [4]           [5]        [6]      [7]
```

`parseNavAll()` read the NAV from a fixed front offset, `cols[4]`. That offset
now lands on `"Direct Plan"`. `parseFloat("Direct Plan")` is `NaN`, the
`!Number.isFinite(nav)` guard fired, and **every data line in the file hit
`continue`**. The existing `cols.length < 6` guard did not catch it either —
8 ≥ 6, so the new format passed the length check and was then mis-read.

Verified against the live feed: the shipped parser returned **0 funds** from a
1.5 MB file.

### Impact

Total outage of the AMFI-backed surface, on prod (`vaspar-pfd` :9999), from
somewhere between 2026-08-16 and 2026-09-02 until today:

| Consumer | Broken call | Effect |
|---|---|---|
| `lib/cron/sip-auto-execute.ts` | `getSchemeCodeByIsin` | **no SIP executed since 2026-08-15** |
| `mutual-funds/refresh-navs` | `getByIsin` | MF valuations frozen; net worth understated |
| `mutual-funds/search` | `searchByName` | fund search returned nothing |
| `mutual-funds` (list/create) | `getByIsin`, `getBySchemeCode` | could not add a fund |
| `mf-redeem-worker`, `[id]/redeem` | `getSchemeCodeByIsin` | a redemption would stick PENDING forever |
| `agent/market-data`, `agent/watchlist/search` | `getByIsin`, `searchByName` | analyst MF signals blind |

Historical NAV (`getHistoricalNavOn`, `getNavHistory`) goes to mfapi.in, not the
AMFI file, and was unaffected — which is why the backfill can price each missed
installment at its true historical NAV.

### Why nobody noticed for three weeks

`runSipAutoExecute` pushes a fund it cannot price onto a `skipped[]` list and
returns **normally**. `cron/tick` only marks a job failed if it *throws*. So
`scheduled_jobs` recorded 90 consecutive `last_run_status = success` runs with
an empty `last_run_error`, while zero SIPs executed. The observability gap is
the more serious half of this bug.

### Fix

1. **`parseNavAll()` is now end-anchored.** NAV is `cols[len-2]`, date is
   `cols[len-1]`, identifiers are `cols[0..2]`, and everything between is joined
   into the display name. Correct for the 6- *and* 8-column layouts, and immune
   to AMFI inserting further descriptive columns in the middle. Rejected
   alternative: bumping the guard to `!== 8`, which breaks on the ninth column —
   same class of bug.
2. **`fetchAndCache()` no longer caches an empty parse.** A non-empty file that
   yields zero funds is a format break, not a quiet day: it logs loudly with the
   first offending data line and serves the stale cache instead of an empty NAV
   universe.
3. **`AMFI_ENDPOINT` pinned to `portal.amfiindia.com`.** `www.amfiindia.com` now
   302-redirects there. `fetch` follows it, so this was not itself breaking us —
   pinned so we do not depend on a redirect AMFI may retire.
4. **`cron/tick` reports non-throwing failure.** New `summariseOutcome()` folds a
   job's own `skipped`/`errors` payload into `last_run_error` even on success,
   prefixed `NOTHING EXECUTED —` when the job did nothing at all. A silent total
   outage is now visible in `scheduled_jobs` and in the container log.
5. **New canary `scripts/check-amfi-nav-feed.mjs`.** Asserts against the live
   feed that NAV is second-to-last, date is last, and ISIN sits in column 2 or 3
   — i.e. the assumptions the parser rests on. Deliberately does not
   re-implement the parser (a copy would drift). Exits non-zero on a break.

### Verification

- Fixed parser against today's live feed: **0 → 14,107 funds**.
- Legacy 6-column fixture still parses correctly (no regression if AMFI reverts).
- 12 of the 13 prod SIP ISINs resolve. The one that does not, `INF966L01A35`
  (demo SIP #77, Quant ELSS), is bad synthetic seed data — that ISIN does not
  exist at AMFI; the real one is `INF966L01986`. Pre-existing and demo-only,
  which is why that SIP has never executed since 2026-07-25. Not fixed here.
- Dry run of the backfill against prod state, then confirmed against the rows
  actually written after redeploy.

### Known, not fixed here

- SIP #74 is dated 2026-09-05 but 09-05 has no published NAV, so it prices at
  the 09-07 NAV while the transaction row keeps the 09-05 date.
  `sip-auto-execute` uses `getHistoricalNav` (value only); the redemption path
  already solved this with `getHistoricalNavOn`, which returns the NAV's real
  date. Worth aligning the SIP path in a follow-up.
- Demo SIP #77's invalid seed ISIN (`INF966L01A35`).
- There is no scheduled job that refreshes MF NAVs — `refresh-navs` is an
  on-demand route only, so between SIP executions the stored NAVs go stale.
