# Changes — 2026-08-14

## Prod recovery: Docker VM wedge (2nd occurrence) → container DNS dead

**Symptom (reported):** slow refresh, Telegram not updating, "gold not
updating" on the overview.

**Root cause (one fault, multiple symptoms):** the Docker Desktop VM wedged
again (after 2026-07-31). Its control plane hung (`docker ps`/`logs`/`version`
all timed out) while the running container kept serving `/api/health` in ~5ms.
The wedge killed the container's DNS forwarder (`nameserver 192.168.65.7`), so
every outbound hostname lookup inside the container failed with `EAI_AGAIN` —
and failed *slowly* (the resolver retries a dead nameserver ~5-15s before
giving up). Consequences:
- **Telegram silent** — `api.telegram.org` never resolved → `getUpdates` +
  `sendMessage` failed (logs full of `getaddrinfo EAI_AGAIN api.telegram.org`).
- **Overview stuck on spinner** — `/api/investments/stocks` did slow DNS
  lookups for `query1.finance.yahoo.com` that took ~15s each to fail; the
  page's `Promise.all` waited on it.

**Fix (ops):** restarted Docker Desktop (graceful quit hung → SIGKILL survivors
→ relaunch). Daemon back in ~12s; container returned via `--restart
unless-stopped`. Verified: DNS resolves inside the container again, container
reaches `api.telegram.org` 200 + `query1.finance.yahoo.com` 200, no new
`EAI_AGAIN`. Not disk-triggered this time (134 GB free) and no read-only
remount — a distinct failure mode from the July incident.

## Fix: gold value stale in net worth (live-on-read) + external-fetch resilience

Landed on `main` (`a2a30ab`), merged into `feat/analyst-agent` (`eebafcc`),
plus an analyst-scoped follow-up (`e829d3a`). Deployed to vaspar-pfd.

**Area:** `src/lib/services/gold-valuation.ts` (new), `src/app/api/investments/
gold/route.ts`, `src/lib/services/yahoo-finance.ts`, `src/lib/services/ibja.ts`,
`src/app/(dashboard)/page.tsx`.

**Symptom:** gold detail page showed ₹18.42L but net worth showed ₹17.45L for
the same holding (personal: one 125g PHYSICAL row).

**Root cause:** `gold_holdings.current_value` is a *stored* column, written only
on create or the gold page's "Refresh rates" button. The gold page ignores it
and recomputes live off today's IBJA rate; the overview + retirement report
summed the stored value. So they drift the moment the price moves (stored rate
was from 2026-07-12; ~5.6% stale).

**Fix:**
- New `valueGoldRow()` helper — the single source of truth for a row's live
  value (IBJA for physical/SGB/digital, Yahoo unit price for ETF; falls back to
  stored value when a live quote is missing).
- `GET /api/investments/gold` now recomputes value **on read** via that helper
  — read-only (no persist; `/refresh-rates` still owns persistence), fully
  guarded so any rate-service failure returns the stored rows. Net worth +
  retirement report now match the gold page.

**Resilience (the "docker fixes"):** so the VM-wedge class of failure degrades
instead of freezing —
- Every Yahoo + bankbazaar fetch now carries `AbortSignal.timeout` (8-9s), so a
  stalled connection / dead resolver fails fast to stale cache instead of
  hanging ~15s. `getCurrentGoldRate()` is now on the gold GET path, so bounding
  it matters.
- The overview page loads each asset endpoint independently
  (`Promise.allSettled` + a 15s per-fetch timeout) instead of one all-or-nothing
  `Promise.all`, so one slow/failed asset class becomes an empty tile rather
  than freezing the whole net-worth view.
- Analyst-only Yahoo history/intraday fetches got the same timeout on
  `feat/analyst-agent` (`e829d3a`).

**Verify:** tsc + eslint clean. Personal holding 125g × live IBJA rate
(~₹14,736/g incl. India retail premium) ≈ ₹18.4L — net worth now reflects the
live value like the gold page.

**Not addressed (flagged):** the Docker VM has now wedged twice in two weeks —
the restart is a cure, not a prevention. A host-side watchdog (ping `docker
version` + container DNS, alert/auto-restart on wedge) was proposed and left for
Bharath's decision; it's host infra, not repo code, so not part of this deploy.
